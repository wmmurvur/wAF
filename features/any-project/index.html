Any project

One backlog per project, and the project can be anything.

A project is not code. It is a pile of work, the decisions behind it, the people in it and what it costs, and it is all kept in plain files in a folder of your own, readable in Obsidian with nothing running. Every session started on it arrives knowing it, works off the top of your list, and writes back what it did, so the next one starts from there.

07 Backlog

Projects of any kind · the work list · the track

You write the work down. The fleet works it off.

An app, a documentary, a thesis, a campaign: every project has its own page, and the work waits in one plain Backlog.md file. You put it in order; agents take the top of it, item by item, and tick off what they finish. The Track tab remembers how each one was done.

    II·1

    Any kind of project

    Software, a documentary series, a thesis, homework, an ad campaign. Same backlog, different work.

    Four kinds of project, one page

    What it solves

    Tools for agents assume the work is code. A documentary, a thesis or a campaign has the same trouble: a pile of work, decisions nobody should have to make twice, and agents that forget between sessions.

    How it works · pick a step

    If a project's folder goes missing, the project stays, with a warning and three answers: relink, recreate, ignore. Its sessions, cost and timeline keep working, and nothing is ever recreated silently.

    II·2

    Backlog

    Write a thought down in one line. The fleet works the list off in the order you set.

    The backlog, being worked

    What it solves

    A thought that needs a form is never written down. A list kept in a database is unreadable without the tool. And "do the top five" needs an order you set, not the order the lines happen to sit in.

    How it works · pick a step

    Ticking an item changes exactly one character of the file, and adds no date the tool does not own. Closed items are archived at the end of the same file, so a code is never issued twice. A duplicate code is flagged on its row and never corrected for you.

    II·3

    Track

    How every closed item was closed: which session, which turn, what was tried first. The log can be rebuilt from the sessions.

    The Track tab, on demo items

    What it solves

    An item that was not finished leaves nothing behind, so the next agent tries again what the last one already tried. And three months later nobody can say which session fixed K-8, or how.

    How it works · pick a step

    Each item's card puts the size the backlog estimated beside the turns it really took, and the median for that size in this project, once there are enough sized items for a median worth quoting.

    II·4

    Project context

    Every session starts with a brief built from the project's charter, plan, backlog and worklog, so no agent starts cold.

    What every session starts with

    What it solves

    Every new session finds its way around the project by reading the folder, and pays for it in tokens. It guesses where the worklog is, and tries again what was dropped months ago.

    How it works · pick a step

    The brief is kept under 2,500 characters by shortening its lists, never by cutting its last part, which says where to write back. The full text is _AF/BRIEF.md in the project folder, readable by any session.

    II·5

    Handover letter

    Passing a project on? One letter says where everything is, what is open, and what was already tried.

    What it solves

    Handing a project over, to a colleague, to a new agent, or to yourself in three months, costs an afternoon of "where is…" and "did anyone try…".

    How it works · pick a step

    It is not a report. A report covers a period; the letter is a starting position, for whoever starts next.

    II·7

    Cost and analysis

    Weeks, rhythm, how long an item takes from open to closed, and where the money went.

    The project's tabs

    What it solves

    "What has this client cost?" and "how is this project actually worked?" are in the transcripts, but only if every session belongs to a project, and nobody files hundreds of sessions by hand.

    How it works · pick a step

    The Timeline tab joins everything the project touched: sessions, their turns, tasks, missions, commits, decisions and deliveries. A document event appears only with a date the document itself states; the page says so, so a missing row reads as a limit, not a loss.

    Questions

    Does a project have to be software?

    No. A project with no code has no code roots, and that is all. Its backlog holds shots, chapters or posts instead of bugs, and its agents work them off the same way.

    Where is it all kept?

    In the project's folder, as plain Markdown files: the charter, the plan, the backlog and its log, the worklog, decisions and deliverables. Agent Farm keeps only a list of projects and which session belongs to which.

    Can I keep editing in Obsidian?

    Yes. Every write Agent Farm makes checks the file has not changed since it read it, and refuses rather than overwrite a save you made in between. A box you tick in Obsidian is picked up by the track. Any document opens where you like it: in VS Code, its preview, Obsidian or your own app.

    Do Codex and the other engines get the project brief?

    Yes, in their first prompt, since they have no system prompt channel. A Codex session you start yourself in a terminal is not told, and Agent Farm says so rather than typing into your terminal for you.

    I have months of sessions from before projects. What about them?

    Agent Farm proposes where each one belongs, with reasons you can check: it wrote these files, its folder's other sessions are filed here, its agent mostly works here. A close call is shown as one and left out of "select all". Nothing is filed until you approve it.

    What if I rename or move the folder?

    Renamed in Obsidian, it is recognised as the same project on the next rescan. Moved somewhere Agent Farm cannot find, the project stays with a warning and asks you to relink, recreate or ignore it.
