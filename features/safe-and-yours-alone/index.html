Safe and yours alone

Guards stop what an agent should not do, and nothing about your work comes to us.

Your work stays on your machine. The free version never contacts us; a paid licence checks its key once a day, and that is the whole message. Your engines talk to their own providers, and anything else Agent Farm reaches is a service you switch on. On the machine, guards stop an agent before a command runs, not after: one for the shell, one for disk searches, one for permissions, one for keys and one for the browser.

X·3

ShellGuard

Before a shell command runs, the shapes that garble or hide it are refused: non-ASCII, backticks, long heredocs, long quoted text. The agent is told the safe way: write the text to a file.

What it solves

Agents write long shell commands. Some arrive garbled, a character re-encoded on the way, and some run more than they show, a second command inside a backtick. Neither is visible until it has run.

How it works · pick a step

The backtick rule applies where the shell is bash: Claude Code, Git Bash. Codex's shell on Windows is PowerShell, where a backtick is the escape character, so there it is not refused.

BridgeGuard

An agent that goes searching the disk for a session by its id is stopped and sent to the bridge, which reads it properly.

Session 7c41e2a0, picked up by its id

What it solves

An agent asked about an old session goes looking for it on disk: a recursive search through every CLI's folders for its id. It burns context and quota, and those folders and their formats change with each CLI release.

How it works · pick a step

Each stop is logged and leaves a mark on that session's Console card.

X·5

Permissions as shown

The permission a card shows is the one in force; if a policy forbids it, the session is refused, never quietly downgraded. A lint finds blanket allows and dangerous patterns.

What it solves

When a card says one permission and the process runs under another, a session you set to bypass can sit for an hour on a question nobody sees, and one you thought would ask goes ahead.

How it works · pick a step

An agent can answer a session's question over the bridge, but it can never grant a tool permission. That stays your call, in the panel.

Keys kept out

Route keys are scrubbed from whatever a run prints, and Gatekeeper's log keeps only a hash and a length of what it read.

Secrets on the home page

What it solves

A key handed to a run ends up in what the run prints: a request line, an error, a config dump. Archived, that output is your key in plain text in a file.

How it works · pick a step

A secret can be marked farm only: Agent Farm still uses it, but no agent's task receives it. The Gatekeeper key starts that way. And a key found in plain text in a config file is reported, so you can move it to the vault.

Browser on a leash

A browser step opens only the sites on its allow list, or fails without running, and asks you before each run unless you chose otherwise.

What it solves

An agent with a browser can follow a link anywhere. A step that runs at night has nobody watching where it goes.

How it works · pick a step

The agent's prompt carries hard rules as well: open no link off the list, never make up a sign-in, and report NO BROWSER MCP when there is no browser. A login wall on a recipe step is reported as LOGIN NEEDED, never typed into.

Superpowers

Engineering disciplines on disk, such as tests first and systematic debugging, with quality gates.

Questions

Does anything about my work come to you?

No. The free version never contacts us. A paid licence checks its key once a day, and that message holds the key, a hash of the machine and the version, nothing else. Your code, prompts, transcripts, names, costs and the features you use never come to us.

What does a paid licence do without a connection?

It keeps working for 30 days without reaching us. The check only asks whether the key is valid; nothing runs on our side.

Who sees my prompts, then?

The provider of the engine you run, as without Agent Farm: Anthropic for Claude Code, OpenAI for Codex, Google for Gemini and Antigravity, and the providers you give OpenCode. A route sends a run to the provider you picked for it.

Does Agent Farm sandbox my agents?

No. It maps its permission choices onto each engine's own: Claude Code's permission modes, Codex's sandbox, Gemini's approval mode, Antigravity's mode, OpenCode's plan agent. Parallel runs work in separate git worktrees. The guards on this page stop the commands that should not run.

Do the guards work on every engine?

They act in the hook an engine runs before a tool: Claude Code's, and Codex's. BridgeGuard reports for each engine whether a hook covers it, so an engine without one is never assumed to be guarded.

Can I let one command through?

Yes, on purpose and one command at a time: af:allow-shell for ShellGuard, af:allow-id for BridgeGuard. It is written into the command, so the session's transcript shows every time it was used.
